# Docker Deployment

## Published image

CI publishes a **clean** image (no bundled Palworld game data) to GitHub
Container Registry on each release:

```text
ghcr.io/dhampyru/palworld-dashboard:latest
```

Pull and run it directly (minimal example in the README). Caveats of the clean
image:

- the save inspector shows raw **IDs**, not names — no bundled game data; add
  names via [Item & Pal Datasets](/docs/configuration/item-pal-datasets) (needs a
  source build);
- the connect address in the header/Invite is a **placeholder**
  (`NEXT_PUBLIC_GAME_SERVER_IP` is baked at build time).

The repo's default `docker-compose.yml` **builds from source**, so those two are
customizable there. Use the prebuilt image when you want a fast, no-build install.

## Ports

The container listens on port `3000`. Change the host port with:

```env
PALWORLD_SERVER_DASHBOARD_PORT=3001
```

Then open:

```text
http://localhost:3001
```

## Persistent volumes

Compose defines:

| Volume | Purpose |
| --- | --- |
| `palworld-dashboard-data` | Panel credential hashes. |
| `palworld-fps-metrics` | FPS history ring. |

Do not delete `palworld-dashboard-data` unless you intentionally want to reseed panel passwords.

## Recreate cleanly

```bash
docker compose up -d --force-recreate
```

## Remove stack

```bash
docker compose down
```

This keeps named volumes. To delete volumes too:

```bash
docker compose down -v
```

Only use `-v` if you understand that it removes dashboard credential state and FPS history.
