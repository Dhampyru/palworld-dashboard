# Live Map Art (world-map background)

The Live Map's world-map background and marker glyphs are **bundled with the
dashboard** — no setup required. They're inherited, unchanged, from the upstream
project [RNZ01/palworld-server-dashboard](https://github.com/RNZ01/palworld-server-dashboard)
(MIT); see [Acknowledgments](../../README.md#acknowledgments).

This page is just a reference for anyone who wants to **replace or update** the
map art (e.g. swap in a higher-res or updated-for-a-new-patch map).

## Files

They live in `public/palworld-map/`:

| File | Purpose | Format |
| --- | --- | --- |
| `full-map-native-8192.webp` | Default ("world") map | WebP, 8192×8192 |
| `full-map-tree-8192.webp` | The "tree"/terrain layer (Layers toggle) | WebP, 8192×8192 |
| `full-map-z4.png` | Firefox-safe fallback | PNG, 4096×4096 |
| `player.webp`, `fast_travel.webp`, `boss_tower.webp` | Marker glyphs | WebP |

(`*.avif` variants may also be present; the app currently loads the WebP/PNG set
above.)

## Replacing the map

Drop replacement files in with the **same names**, then rebuild:

```bash
docker compose build palworld-server-dashboard
docker compose up -d palworld-server-dashboard
```

> **Alignment matters.** The map→screen transform assumes each image spans the
> **full world at exact bounds**. A cropped, padded, or differently-projected
> image will make markers land in the wrong place — keep replacements at the same
> bounds and aspect as the originals.

## Troubleshooting

- **"Map image failed to load"** — a file is missing or misnamed under
  `public/palworld-map/`, or you didn't rebuild (static assets are baked at build
  time).
- **Markers offset after a replacement** — the new image isn't the full map at
  the same world bounds as the original.
