## ⚠️ Hard-won facts (critical — don't relearn these)
- **UE4SS builds have TWO layouts.** Stable/Experimental = **FLAT** (`UE4SS.dll` + `Mods/` at `Win64/`
  root, beside `dwmapi.dll`). PalSchema/experimental = **MODERN** (everything under `Win64/ue4ss/`).
  **Install each in its native layout** — the old code force-nested flat under `ue4ss/`, so the flat
  dwmapi proxy couldn't find `UE4SS.dll` → **UE4SS silently never injected** (game ran mod-less / into
  a Steam re-verify loop).
- **C++ mods are ABI-locked to their UE4SS build.** PalSchema's `dlls/main.dll` imports from a specific
  `UE4SS.dll`; migrating it onto the Stable build → `wine: ... unimplemented function
  UE4SS.dll.get_working_directory ... aborting` → **game crash on boot**. The installer now **skips any
  mod with `dlls/*.dll` from cross-build migration** and drops its `mods.txt` line. Lua/Blueprint mods
  migrate fine.
- **Official/Stable builds lack Palworld's preconfigured `MemberVariableLayout.ini`** (the single most
  important file the Okaetsu build ships). Stable runs *classic* Lua/BP mods but **cannot run
  PalSchema**. Even classic mods may use experimental-only Lua APIs (RarePalAppearanceLua errors
  `GetGameInstance` nil on Stable — works on PalSchema).
- **The `UE4SS.log` banner only rewrites on a successful boot injection**, so it's not proof of the
  *current* state. Trust it only when its timestamp post-dates the container `startedAt`; otherwise
  it's stale (a silent injection failure leaves the old banner → phantom "active").
- **`readUe4ssStatus` is now layout-aware** (checks `ue4ss/` OR flat `Win64/UE4SS.dll`, reads either log
  location). A flat install previously read as "not installed" → the whole loader UI vanished.
- Every swap **auto-backs-up** to `game/backups/ue4ss-*.tar.gz` (now captures flat artifacts too);
  rollback wipes both layouts first. A labeled `ue4ss-SAFEPOINT-palschema-*` backup is also present.

## Ops cheat-sheet
- **Typecheck** (no node on host):
  `docker run --rm -v /root/palworld-dashboard:/app -w /app node:20-alpine npx tsc --noEmit`
- **Build+deploy**: `docker compose build --no-cache palworld-server-dashboard && docker compose up -d`
  (in `~/palworld-dashboard`)
- **Verify a real game restart** by container `StartedAt` changing, not exit code. Lifecycle actions go
  through `/run/palworld/*.request` flag files (host systemd units) — the dashboard never gets
  docker/sudo.
- **Working style**: one feature at a time; typecheck→build→deploy→verify→commit; **commit/push only
  when asked**; roadmap items need an explicit "start item N"; never touch `~/palworld-server/` except
  read-only unless the task is explicitly about the game server.
